Upload Custom Configuration Files here:



This can be a plain table of elevations whose size the config states, or a DEM the page reads for itself: an ESRI ASCII grid (.asc) or a GeoTIFF (.tif), in UTM or in latitude and longitude, which is projected to the UTM zone of its centre. A DEM sets the grid, the cell size, the georeference and the elevation range of the config uploaded with it, so that config only has to be a case of the kind you want: its physics, friction and run length are kept, and the source or the failure surface it carried is moved to the centre of the domain, to be placed on the map. Cells with no data are filled from their nearest valid neighbours.









Boundary time-series files can be loaded for boundary type 5 and should contain station locations plus time, eta, hu, and hv columns. See the Users Forum for details on how to construct these OPTIONAL boundary time series files.

For image overlay, you have two choices. If you have a high-resolution satellite or aerial image, you can load that file below. Note that this image must cover the exact area as the loaded bathy/topo, or the overlay will not be spatially matched. Alternatively, if you know the lat/lon coordinates of the corners of the bathy/topo, you can specify these in the input json file (see examples). Based on these corner coordinates, the code will download a Google Maps tile for the domain, and use that as an overlay.


Experimental feature: To add 3D models to the "Explorer" view, upload a model json file. Details on the format of this file can be found here.

Write Single 2D Surface Options:





Time Stacks of 2D Surface Data Write Options:











Click the button below to start the writing of 2D surface data to files. Data will be written in raw binary for surface data, and ASCII for time and coordinate data. You can use this example Matlab script to plot the data. Note that writing data to files will slow the simulation, and will tend to make the user interface sluggish; when writing data files frequently (>10 writes per wave period), no to minimal interaction with the simulation is recommended. See the console for progress messages.




Nested Grid Boundary Time Series Output Options:
Define a rectangle using 0-based lower-left and upper-right grid indices. The four rectangle edges will be saved as eta/hu/hv time-series boundary files for one-way nested grids.
These controls edit the legacy/first rectangle. Additional rectangles can be supplied in config.json with nestedGridOutput_rectangles; default output prefixes are gridD, gridD2, gridD3, etc.
